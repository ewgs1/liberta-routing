# Участие в проекте

Предлагайте небольшие изменения с первичным официальным источником, датой проверки и собственным описанием факта. Не присылайте скопированные routing-базы, геоданные, массовые подборки или чужой код с неизвестным происхождением.

Новый хост сначала имеет статус `candidate`. Проверьте владельца и назначение, отдельно соберите сетевые наблюдения и пользовательские сценарии. В alpha одобряются только точные хосты. Изменение direct-маршрута требует осознанного review и обновления `route-lock.json` с причиной; само изменение hash не означает одобрение другим человеком.

После изменения данных повысьте версию в `package.json` и `registry.json`, соберите новый каталог. Существующие каталоги выпусков не изменяются. Запустите `npm run verify`, изучите diff и результаты CI. Проверяющий должен посмотреть новые домены, расширение direct, отсутствие секретов и совпадение экспортов.

Не отправляйте публично исходные конфиги подписок, токены, идентификаторы пользователей/узлов, локальные адреса, полный HAR, сырые canary-отчёты и документы об инфраструктуре. В issue достаточно публичного домена, версии правил/клиента, ожидаемого и наблюдаемого поведения без личных данных.
