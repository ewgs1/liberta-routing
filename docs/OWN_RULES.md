# Собственные подключаемые списки

Основной результат проекта — наборы данных из собственного реестра Liberta, а не прежний полный профиль Xray. Ветка `release` содержит только готовые списки, manifest и документацию. Публикация в неё выполняется вручную после проверок. GitHub Release `v1.0.0` остаётся прежним сохранённым выпуском; его тег и файлы автоматически не переписываются.

| --- | --- |
| liberta-direct | Все 168 доменов из 13 классов с policy: direct в текущем исходнике |

| liberta-payments | Платёжные сервисы |
| liberta-gov | Государственные сервисы |
| liberta-telecom | Операторы связи |
| liberta-marketplaces | Маркетплейсы |
| liberta-retail | Магазины |
| liberta-delivery | Доставка |
| liberta-taxi | Такси |
| liberta-transport | Транспорт |
| liberta-medicine | Медицина |
| liberta-media | Медиа |
| liberta-social | Социальные сервисы |
| liberta-jobs-realty | Работа и недвижимость |

Для каждого набора существуют `.domains.txt`, `.singbox.json` и `.xray.json`. Все форматы совпадают по составу и включают домен с его поддоменами. Подстроки внутри чужого домена не совпадают. Список не включает всю зону ru/su/рф и не направляет все российские IP напрямую.

В старом шаблоне explicit:false означал, что класс покрывался внешними геобазами. В независимом наборе эти классы включены явно, как и остальные классы с policy: direct. База не сокращена с 111 до 45.

## sing-box: подключение по URL

Общий source rule-set:

https://raw.githubusercontent.com/ewgs1/liberta-routing/release/liberta-direct.singbox.json

Внутри существующего `route` добавьте remote rule-set с тегом `liberta-direct`, форматом `source` и этим URL. Правило с `rule_set: ["liberta-direct"]` направьте в ваш существующий outbound `direct`; общий маршрут задайте через `route.final: "proxy"`. Для категорий меняется имя файла и тег.

Это часть существующей конфигурации, не VPN-подписка. Подключение, DNS, TUN и служебные правила остаются в клиентском шаблоне. Загрузку списка через нужный выход настройте по версии sing-box; в 1.14 механизм HTTP-клиента изменён. Для испытания без сетевой загрузки скачайте файл и используйте local/source rule-set.

Ветка release — канал обновлений после ручной публикации. Для закрепления проверенной версии замените `release` в URL на SHA коммита ветки с данными. `manifest.json` указывает SHA исходного кода, количества и контрольные суммы файлов. Одна только сумма, скачанная из того же недоверенного источника, не доказывает подлинность.

## Xray: правило и полный тестовый шаблон

https://raw.githubusercontent.com/ewgs1/liberta-routing/release/liberta-direct.xray.json

Файл содержит один объект правила для массива `routing.rules`. Разместите его перед общим правилом proxy. Это JSON-правило, а не geosite.dat: Xray сам не загружает такой файл по HTTP как удалённую геобазу. Обновление должно выполняться сборщиком шаблона или средствами конкретного клиента.

Для Remnawave подготовлен отдельный полный шаблон:

`examples/remnawave/liberta-selective.xray.json`

В нём 168 доменов и их поддомены идут direct, остальные публичные назначения — proxy. Сохранены локальные исключения, правила для DNS-резолверов и блокировка BitTorrent. В DNS и маршрутах нет geosite/geoip/ext ссылок. Приватные сети перечислены явно; российские публичные подсети целиком не добавляются.

Публичный IP без известного имени попадает в proxy. Сниффинг HTTP/TLS может восстановить имя для доменного правила, но это зависит от протокола и клиента. Этот режим не обещает исключение всего трафика банков. Недостающие зависимости и границы проверки описаны в [разборе покрытия](COVERAGE.md).

Создайте отдельный XRAY_JSON-шаблон для тестового пользователя, вставьте этот JSON целиком и проверьте выданную подписку в совместимом приложении. Remnawave должен подставить proxy через addVirtualHostAsOutbound. В репозитории нет адресов VPN-узлов и подключений пользователей.

## Что проверено

Тесты проверяют весь текущий реестр, поддомены, отрицательные примеры, согласованность форматов, 13 категорий, контрольные суммы и отсутствие геобаз. CI дополнительно проверяет полную выборочную конфигурацию Xray с тестовым proxy и source rule-set в двух закреплённых версиях sing-box. `npm run verify:routing` проверяет реальные соединения через Xray с двумя выходами-наблюдателями на локальном компьютере: имена, поддомены, отрицательные примеры, публичные IP без имени и HTTP-сниффинг. Внешние сервисы в этом испытании не опрашиваются.

Это проверка логики и парсеров. Вход в сервисы, мобильные API/CDN, TUN/FakeIP, DNS-утечки, IPv4/IPv6 и реальные российские сети проверяются отдельно. Источник каждого исходного домена и статус его дополнительного обзора записаны в registry/provenance.json; отсутствующие даты и измерения не выдумываются.

## Обновление

Измените собственный реестр и provenance, изучите diff выбора маршрутов, обновите контрольные записи после осознанного review, выполните `npm run build` и `npm run verify`. Workflow `Publish own rule sets` вручную публикует проверенные данные в ветку release без принудительного переписывания её истории. Старый рабочий профиль и релиз не активируются и не заменяются этим действием.

Спецификации форматов: https://sing-box.sagernet.org/configuration/rule-set/ ; https://xtls.github.io/en/config/routing.html

Приоритет исключений: добавьте `liberta-proxy` перед `liberta-direct`. Полный пример уже содержит этот порядок. Профили Happ и отдельная интеграция описаны в [HAPP_IOS.md](HAPP_IOS.md).
