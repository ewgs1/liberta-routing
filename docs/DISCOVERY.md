# Обнаружение доменов и сетевых зависимостей

Полнота доменных правил обязательна. Испытания приложений проверяют её и находят пробелы; они не заменяют сбор данных. Количество строк учитывается вместе с их смыслом: суффикс может покрывать множество адресатов, а лишние корни сайтов не закрывают отсутствующую CDN.

`scripts/discover-services.mjs` собирает кандидатов отдельно от действующих маршрутов. Начальные сервисы и первичные страницы перечислены в `registry/discovery-sources.json`. Сейчас настроены Т-Банк, VK, Ozon, Wildberries, Яндекс, Госуслуги и 2ГИС. Это начальная область поиска, не весь российский интернет.

```sh
npm run discover -- --service tbank --out .private/tbank-discovery.json
npm run discover -- --service tbank --ct true --out .private/tbank-certificates.json
npm run discover -- --service wildberries --networks true --out .private/wb-networks.json
```

Выходной файл создаётся отдельно и не перезаписывается. Исходный реестр и правила не меняются. Отчёт содержит кандидатов, источники, дату, хеши полученных страниц, результаты DNS и явные ограничения объёма. Размеры ответов, число запросов и время ожидания ограничены. Выход за бюджет или недоступность источника не превращаются в успешный полный сбор.

## Что реализовано

| Канал | Что собирает | Чего это не доказывает |
| --- | --- | --- |
| Первичные страницы | URL и доменные имена из текста документов, ссылки на разрешённые JS/CSS, адрес редиректа | Все ссылки не обязательно принадлежат компании и не обязательно нужны приложению |
| CSP | Домены из политик загрузки ресурсов, в том числе при HTTP 403/498 | Политика разрешения не равна факту использования каждого ресурса |
| Публичные JS/CSS | Ссылки на API/CDN; загрузка только из заранее разрешённых пространств сервиса | Динамически собранные имена и все ветви приложения не восстановлены |
| DNS | Наличие A/AAAA и CNAME-имена для ограниченного набора кандидатов | Нет A/AAAA у корня — не значит, что поддомены отсутствуют; CNAME не подтверждает владельца CDN |
| CT через crt.sh | Имена из полученных записей сертификатов | Выпуск сертификата не доказывает текущую работу, принадлежность сервису всех SAN или полноту результата |
| RIPEstat | Проверка держателя настроенного ASN и объявления префиксов с временным окном | Объявления за период могут быть историческими; совпадение держателя не разрешает автоматически весь диапазон |

Новый домен помечается review-required. Для уже покрытого имени сохраняется already-covered, для известных proxy-исключений — proxy-exception. Суффикс не расширяется до родительского домена автоматически. Для общей сети или адреса дополнительно выясняют, какие посторонние сервисы будут затронуты.

ASN Wildberries добавлен как наблюдаемый кандидат по первичному указанию самой компании и отдельно сверяется с RIPEstat. Это не IP-правило и не новый режим маршрутизации. Остальные ASN нельзя вписывать по догадке или совпадению названия.

Workflow `Discover service dependencies` выполняет сбор ежедневно после его попадания в основную ветку и поддерживает ручной запуск. В тестовом PR сбор выполняется в CI. Санитизированные отчёты сохраняются в артефактах конкретного запуска. Они не содержат cookies, тел запросов пользователей, IP сборщика, VPN-узлов или ключей; код и сырые страницы сервисов не публикуются.

## Следующее расширение

- Разбор доменных строк из официально полученных APK с проверкой издателя, версии, подписи и хеша. APK и чужой код не включаются в публичную базу. Статические строки остаются кандидатами, а не подтверждённым трафиком.
- Импорт обезличенных DNS/адресатов из локального испытания приложения. Он нужен для динамических зависимостей, отсутствующих в HTML или сертификатах.
- Рекурсивный обход CNAME с ограничением глубины и обнаружением циклов; сейчас проверяется ответ CNAME для наблюдаемого имени.
- Инкрементальное сравнение двух отчётов и PR с предложенными изменениями. Промоутер должен требовать источник и проверку широты охвата; простое копирование всего отчёта в direct недопустимо.

Сканирование всех российских IP не позволяет получить все домены сервисов: на одном адресе может быть множество сайтов, домены могут использовать зарубежные CDN, а PTR не является перечнем обслуживаемых имён. Сеть сервиса — дополнительный канал инвентаризации, а не замена доменным источникам.

Описание конечной архитектуры: [ARCHITECTURE_DECISION.md](ARCHITECTURE_DECISION.md). Сбор кандидатов, проверка приложений и публикация маршрутов — три необходимые части одного процесса.
