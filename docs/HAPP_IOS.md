# Happ на iPhone: отдельное испытание

Текущий статус: файлы подготовлены; импорт и приложения на физическом iPhone ещё не проверены. Нужны фактические версии Happ, встроенного Xray, iOS и приложений. Сохраняйте рабочую подписку.

## Если сервер добавлен обычным ключом

1. Откройте `examples/happ/liberta-selective.txt`, скопируйте всю строку и импортируйте профиль маршрутизации в Happ. Это профиль правил без узлов и ключей. У него отдельное имя, ссылка `add` не переключает действующие профили автоматически.
2. Выберите его у тестовой подписки и переподключитесь. Встроенные геофайлы могут оставаться в приложении, но наши правила не используют geosite/geoip.
3. Проверьте сценарии ниже сначала по Wi-Fi, затем по мобильной сети. Если интерфейс не позволяет добавить правила, проверьте формат подписки: для полного JSON действует следующий раздел.
4. Отдельный `liberta-selective-fakedns.txt` включает FakeDNS для сравнения. Он помогает сопоставить выданный DNS-адрес с именем, когда запрос прошёл через DNS приложения. Он не распознаёт произвольный заранее известный IP. После переключения закройте проверяемые приложения, переподключите туннель; если сеть не восстановилась, выключите/включите авиарежим для сброса соединений и кэша. Этот вариант не объявлен производственным.

## Если подписка передаёт полный Xray JSON

По документации Happ такой JSON передаётся ядру 1:1. Native-профиль выше не заменяет его routing/DNS. Параметры Tunnel DNS управляют окружением туннеля отдельно; поведение зависит от версии клиента и метаданных подписки.

Используйте отдельный шаблон `examples/remnawave/liberta-selective.xray.json` в Remnawave для тестовой подписки. Панель добавляет outbound `proxy`. Сам файл без этого outbound не является готовым подключением. Для уже полного локального Xray JSON:

```sh
node scripts/integrate.mjs --mode selective --format xray --base .private/base.json --out .private/selective-test.json
```

Команда сохраняет настройки соединения, меняет только DNS/маршруты/sniffing в отдельной копии, не активирует её. Поддержаны локальные SOCKS/HTTP клиентские слушатели и стандартные теги proxy/direct/block. Неизвестные схемы, существующий FakeDNS и балансировщики требуют отдельного разбора; скрипт откажется изменять их вслепую. Исходный файл не перезаписывается, готовый приватный конфиг в GitHub не публикуется.

## Приёмка

| Сервис | Действия |
| --- | --- |
| Т-Банк | Холодный запуск, вход, список счетов, история, открытие СБП до подтверждения перевода |
| Госуслуги | Вход, профиль, открытие документов |
| VK | Лента, фото, сообщения, видео со звуком, короткий звонок |
| Яндекс / 2ГИС | Карта, поиск, построение маршрута; Яндекс Музыка при наличии доступа |
| Ozon / Wildberries | Поиск, несколько карточек с фото/видео, корзина, пункт выдачи, экран оплаты без покупки |
| Зарубежный сайт | Открыть GitHub и проверить, что его соединение остаётся proxy |

Для каждого сценария записывают сеть, версии, хеш конфигурации/набора, результат и время. Для сбоя нужны имена адресатов и выбранный маршрут; не отправляйте URL с параметрами, заголовки, cookies, номера счетов и ключи подписки. Успешная загрузка страницы сама по себе не доказывает direct: маршрут подтверждается локальным журналом клиента, если он доступен.

Официальные описания формата: https://www.happ.su/main/ru/dev-docs/routing и https://www.happ.su/main/ru/dev-docs/examples-of-links-and-parameters .

Нативная проверка полного JSON использует закреплённый Xray 26.11.9. Версию ядра внутри Happ необходимо записать перед импортом; принятие JSON другим ядром здесь не подтверждено. Полный шаблон пока сохраняет IPv4-стратегию DNS прежнего профиля; сеть только с IPv6/NAT64 ещё не испытана.
